# 产品需求与信息架构

## 一级页面

### 1. 项目首页

- 一句话解释“参考图变成可复用工作流”。
- 提供创建项目、打开本地项目、查看预置案例三个入口。
- 展示当前模型状态，不要求无Key用户先配置。
- 产品文案只承诺静物商品场景图。

### 2. 视觉配方

- 上传1至5张用户有权使用的参考图。
- Seed输出12个视觉字段、置信度和图像区域证据。
- 明确展示必须保持、允许变化、禁止出现三组约束。
- 用户可以修改、确认和锁定字段。
- 用户确认后才可生成工作流。

### 3. 工作流画布

固定主干：`输入 → 分析 → 配方 → 生成 → 验收`。

首版节点：

1. ReferenceInput
2. ProductInput
3. RecipeExtractor
4. IdentityLock
5. SceneGenerator
6. ResultAuditor
7. TargetedRepair

规则：

- 输入、生成和输出节点不可删除。
- 分析、锁定和验收可跳过，但界面必须提示风险。
- 修复节点只在验收失败后启用。
- 不允许循环、悬空边和任意自定义代码。
- 画布编辑和批量执行必须使用同一个WorkflowDefinition。

### 4. 批量运行

- 最多5件商品，每件2至3张图片。
- 用户必须确认图片分组，系统不得自行永久决定哪些照片属于同一商品。
- 展示商品名称、图片组、状态、当前步骤、耗时、调用量、验收、问题数、重试次数和操作。
- 操作限于查看、暂停、重试和跳过。
- 同时分析2件，同时生成1件，自动修复最多1次。
- 批量开始前展示预计和最坏调用次数，用户确认后运行。

### 5. 结果与报告

- 按商品展示原图、生成结果、身份评分、配方评分、问题和修复记录。
- 结果状态为通过、警告、失败、需要人工确认。
- 支持筛选和前后对比。
- 导出图片包、视觉工作流JSON和验收报告HTML。

## 模型设置弹窗

- 公开版固定火山方舟官方Base URL。
- 用户填写API Key、Seed Endpoint和图片Endpoint。
- Key只保存在sessionStorage；关闭标签页或断开连接时清除。
- 不提供“永久记住Key”。
- 公开代理不接受任意Base URL。
- 无Key时始终可以进入预置案例。

## 预置案例

- 只读取真实保存的运行结果。
- 标注“真实运行的保存结果”和“当前为只读案例模式”。
- 可以浏览节点、证据、结果、失败和修复。
- 禁止伪造正在运行的动画或模拟模型调用。

## 素材边界

- 产品不搜索或抓取外部平台图片。
- 用户必须确认拥有素材使用权。
- 不提供去水印、Logo复制或人物复刻。
- 产品只迁移可描述的构图、光线、色彩、背景和氛围规则。
