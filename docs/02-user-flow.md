# 用户流程、状态和失败路径

## 默认流程

`创建项目 → 上传参考图 → 提取视觉配方 → 人工确认 → 自动创建工作流 → 上传商品并分组 → 单件试跑 → 确认批量成本 → 批量生成 → 双重验收 → 自动修复一次 → 人工处理剩余失败 → 导出`

## 无密钥用户

`首页 → 打开预置案例 → 查看配方证据 → 查看画布 → 查看批量结果 → 比较修复前后 → 查看实验报告`

## 自带密钥用户

`模型设置 → 测试连接 → 创建项目 → 运行主流程`。

## 自部署用户

`克隆仓库 → 配置环境变量 → 安装依赖 → 运行测试 → 启动或部署 → 创建项目`。

## 两个人工闸门

1. 视觉配方确认：用户确认视觉规则和商品无关的迁移边界后，才能开始生成。
2. 高风险修复确认：出现商品形态、Logo、材质或虚构文字问题时，默认暂停并请求确认。

## 商品任务状态机

`draft → queued → analyzing → generating → auditing → passed|warning|failed|needs-review`

可选转移：

- `failed → repairing → auditing`
- `warning → passed`，仅用户确认后。
- `paused → queued`
- 页面刷新时，进行中的请求变为`interrupted`，由用户恢复，不能伪装仍在运行。

## 错误隔离

商品级错误只影响当前商品：图片损坏、模型拒绝、生成失败、验收失败、修复失败。

系统级错误暂停整批：API Key无效、额度不足、Endpoint不存在、连续网络失败、服务端配置错误。

## 用户错误与诊断信息

用户层显示原因和下一步；诊断面板显示脱敏requestId、Endpoint掩码、HTTP状态、错误分类、节点、耗时和重试次数。禁止显示Key、完整请求头或未脱敏原始响应。
