# 第三期投稿：文章证据与叙事计划

状态：项目主体已完成，可以进入文章阶段；完整正文必须等最小真实实验完成后再定稿。

## 1. 中心承诺

> 把“照着参考图生成商品图”从一次不可控的尝试，变成一条可以分析、编辑、试运行、发布并批量复用的视觉工作流。

目标用户：需要持续制作电商静物场景图，但不希望每次都重新猜提示词的个人创作者与小型团队。

文章不以“35 个节点”或“做了一个复杂平台”为中心。核心问题只有一个：

> 同一件商品，直接写一句提示词生成，与先理解参考图、再编辑提示词生成，结果有什么可观察的差别？

## 3. 最小真实实验

不必完成原计划中的 30 张大评测。投稿前完成下面这组最小实验即可。

### 输入

- 1 组有权使用的参考图。
- 3 件外形、材质不同的静物商品。
- 每件商品 1–3 张清晰图片。

### 对照

对每件商品执行两种流程：

| 组别 | 流程 |
| --- | --- |
| A：直接生成 | 商品图 + 一句人工提示词 → 商品场景生成 |
| B：工作流生成 | 参考图分析 → 提示词编辑/优化 → 商品场景生成 |

保持图片模型、比例、分辨率和生成数量一致。每种流程每件生成 2 张，共 3 × 2 × 2 = 12 张。

### 人工评分

每张图使用 1–5 分记录：

1. 商品外形是否保持。
2. 颜色、材质和结构是否失真。
3. 构图、光线和背景是否接近参考目标。
4. 是否适合作为电商场景图。

同时记录：

- 首次生成是否可用。
- 人工修改提示词的次数。
- 单件耗时。
- 文本/视觉模型调用次数。
- 图片生成调用次数。
- 失败、警告与人工接受情况。

这是一组小样本案例，不写成普遍结论。

## 4. 必须保留的失败案例

至少保留一次真实失败，例如：

- 商品形状或 Logo 发生变化。
- 材质被错误替换。
- 参考图中的原商品被模型带入结果。
- 构图接近，但电商主体不够突出。
- 提示词优化引入了原图没有的商品事实。
- 节点输入、接口或 Schema 校验失败。

记录四张证据：失败输入、失败结果、修改动作、修改后结果。文章需要说明人的判断如何改变了工作流，而不是只展示一次成功。

## 6. 正文大纲

### 开场：先给结果

- 放参考图、3 件商品和 A/B 结果矩阵。
- 用 3–5 句话交代做了什么、为什么做、观察到什么。
- 插入 10–20 秒操作视频或最终成品 GIF。

### 第一部分：我真正遇到的问题

- 电商参考图很好找，但很难说清它为什么好。
- 直接图生图不可解释，也很难稳定迁移到下一件商品。
- 真正要保留的是画面语言，不是参考图里的原商品。

### 第二部分：我把一次生成拆成一条工作流

只讲四个核心节点：

1. 参考图分析。
2. 提示词编辑与优化。
3. 商品场景生成。
4. 结果展示与复核。

不逐项介绍 35 个节点。规划节点只在边界部分一句带过。

### 第三部分：Seed 真正做了什么

- 从参考图提取构图、光线、背景与色彩信息。
- 形成可编辑的提示词建议。
- 根据商品图与提示词生成新场景。
- Coding 过程完成画布、节点、发布版本和批量复用。

每项能力旁边放对应输入、输出或界面证据。

### 第四部分：直接生成和工作流生成的对照

- 展示 A/B 同条件结果。
- 放评分表，不只挑最好的一张。
- 解释哪些差异来自参考图分析，哪些仍需要人工判断。

### 第五部分：一次失败比一次成功更重要

- 展示失败图。
- 说明系统或人如何发现问题。
- 展示修改的提示词/参数。
- 展示修复后结果，并说明仍存在的不足。

### 第六部分：为什么还需要发布版本和批量任务

- 单次成功不能自动复用。
- 发布版本把已经确认的节点、配置和连线固定下来。
- 批量任务替换商品输入，复用同一视觉流程。

### 结尾：边界与判断

- 这是小样本案例，不宣称普遍提升。
- 规划节点尚不可执行。
- 生成结果仍需人工复核商品身份与文字。
- 项目不提供额度，用户需要自己的模型配置。
- 提供 Demo、录屏、仓库和复现说明。
