# 豆包工作首轮开发任务书

## 身份和边界

你是本项目唯一负责工程初始化与代码生成的规定模型。当前目录只有产品文档。必须自行完成技术选型、项目初始化、代码、测试和构建配置；不得恢复其他模型生成的脚手架，不得复制SellerPic源码。

## 开始前

1. 完整阅读`docs/00-project-brief.md`至`docs/10-acceptance-matrix.md`。
2. 列出已理解的用户、核心矛盾、MVP、不做项、停止线和验收条件。
3. 检查本机Node、包管理器和Git环境。
4. 输出简短工程计划后开始执行，不要只停留在方案。

## 首轮目标：只完成模型探针台

首轮不开发完整产品，只建立可以验证三项探针的最小应用：

1. 上传1至5张参考图，调用Seed输出12字段VisualRecipe。
2. 上传同一商品2至3张图片，输出IdentityFeature候选。
3. 上传结果图，运行验收并输出通过、警告、失败或需要人工确认。
4. 所有输出经过Schema校验，并展示证据、置信度、原始输出状态和脱敏诊断。
5. 提供火山方舟BYOK设置；Base URL固定，Key只存在sessionStorage。
6. 提供无Key的真实样例数据入口；若尚无真实结果，明确标记“等待真实运行”，不得伪造。

## 工程要求

- 自行选择并初始化适合的TypeScript Web工程。
- 模型代理不得记录Key或接受任意Base URL。
- 图片内文字不得被当作系统指令。
- 原始模型输出与解析结果分开保存。
- 编写Schema、错误分类、状态转换和敏感信息处理测试。
- 实际运行类型检查、测试和生产构建。
- 更新`docs/08-daily-log.md`，记录命令、失败、修复和真实结果。

## 验收

- 三类输入均有可操作界面和明确状态。
- 合法模型输出可以解析；非法输出被拒绝且不导致页面崩溃。
- Key不进入localStorage、IndexedDB、Git、URL、日志和导出文件。
- 无Key时仍能进入只读样例或等待状态。
- 只有真实命令成功后才能宣布测试或构建通过。

## 首轮禁止

不得开发正式画布、批量生成、自动修复、账号、数据库、支付、部署、多模型适配和其他电商图片工具。

## 完成报告

提交实际文件清单、技术决策、真实命令及结果、失败与修复、未完成项、风险和下一阶段建议。不得虚构模型准确率或实验结果。
