状态：自定义工作流阶段修订。
本文件定义**公开官网 → 工作台 → 项目/草稿/版本/运行**的整体信息架构。
画布布局与交互见 `12-canvas-workspace-spec.md`；自定义工作流领域模型与执行见
`15-custom-workflow.md`；公开官网细节见 `16-marketing-site.md`；视觉与组件见
`13-ui-design-system.md`；验收见 `14-ui-acceptance-matrix.md`。
旧版“固定节点、只读连线”的 IA 表述已被 docs/12、docs/15 取代。

## 1. 产品分层

```
公开层（无需 Key/项目）
  官网 Landing → 产品定位/功能/场景/流程/案例/BYOK 与隐私 → 进入工作台
工作层（登录态概念，本机多项目，无账号体系）
  项目列表 → 项目（聚合一个工作流的草稿/版本与多次运行）
对象层
  项目 Project
    ├─ 工作流草稿 WorkflowDraft（可编辑、可带错保存）
    │    └─ 发布 → 工作流版本 WorkflowVersion（不可变、内容寻址）
    ├─ 运行 Run（单件试运行 / 批量运行，引用确定的 versionId）
    │    └─ 节点执行、生成版本 V1/V2、验收、修复、诊断
    └─ 素材 Asset（参考图/商品图/生成结果，含使用位置）
```

核心用户对象关系：**项目 1—N 工作流版本；版本 1—N 运行；运行 N—N 素材**。
用户进入项目的单一核心任务：编辑并发布一条可解释、可确认、可执行、可验收、可复用的视觉生产流程，然后用它出图。

## 2. 全局路由

| 路由 | 页面 | 访问 | 主要任务 |
|---|---|---|---|
| `/` 或 `/home` | **公开官网** | 公开 | 理解产品、查看流程/案例/隐私，进入工作台 |
| `/projects` | 项目首页 | 工作层 | 创建、搜索、打开项目 |
| `/projects/:id/canvas` | 视觉工作台（默认） | 项目内 | 编辑草稿、发布版本、单件试运行 |
| `/projects/:id/batch` | 批量任务 | 项目内 | 选用**已发布版本**处理多组商品 |
| `/projects/:id/assets` | 素材库 | 项目内 | 管理参考图、商品图、生成结果 |
| `/projects/:id/runs` | 运行记录 | 项目内 | 按运行查看节点时间线、版本、错误与复现 |
| `/projects/:id/runs/:runId` | 单次运行详情 | 项目内 | 一次执行的完整证据与产物 |
| `/projects/:id/settings` | 项目内设置 | 项目内 | 项目信息、模型连接、生成默认值 |
| `/settings` | 设置 | 工作层 | 无项目时的模型连接（标签页会话、全项目共用） |

规则：
- `/` 公开；应用内导航不强制经过官网，老用户可直达 `/projects`。官网“进入工作台”跳 `/projects`。
- 探针不再有任何一级/平级入口；配方、身份、验收是画布节点（docs/12、docs/15）。
- 画布 URL 可带只读参数：`?version=v3` 查看已发布版本、`?run=<runId>` 叠加某次运行结果。
- hash 路由保持（自部署静态服务器零配置即可刷新）。

## 3. 应用壳层（两种语境）

### 3.1 公开官网壳
独立营销布局，无项目侧栏；顶部仅品牌、锚点导航、“进入工作台”CTA；内容纵向滚动，最大内容宽度约束。见 docs/16。

### 3.2 工作台壳（专注式）
项目内统一固定视口 `100vh`：
- **56px 顶栏**：返回项目、当前工作流名 + 草稿/版本徽标、保存态、运行/发布、模型状态灯。
- **56px 收窄主导航轨**（图标+tooltip：工作台/批量/素材/记录/设置），可临时展开 208px，但画布默认专注不展开。
- 主工作区按页面独立滚动；画布内部自行管理浮动层（节点库浮层、覆盖检查器、运行抽屉），见 docs/12。
- 1024px 以下：导航固定 56、覆盖面板全宽；不承诺手机上完整编辑画布，但手机可查看结果与审批。

## 4. 页面规格

### 4.1 公开官网 `/`
定位为“面向首次访问者解释产品”，不是应用首页。完整规格见 docs/16：
- 一句话定位 + 主 CTA（进入工作台 / 了解流程）；
- 核心功能（参考图→配方→身份锁定→生成→四维验收→定向修复）、适用场景（电商静物主图/场景图/批量出图）；
- 使用流程（上传、确认、运行、批量）、真实案例位（**没有真实运行前只放示意结构，不伪造客户案例**）；
- BYOK 与隐私说明（Key 仅在本标签页会话、本地代理白名单、数据存本机）；
- 不复制任何成熟产品的品牌、文案或视觉资产。

### 4.2 项目首页 `/projects`
选择工作，不承担模型调试：
- 一句话价值（克制，非营销 Hero）+“新建项目”主操作；
- 最近项目卡片（封面占位、工作流状态、版本号、生成数、待确认数、更新时间）；
- 搜索/排序/状态筛选；首次使用空状态；“从标准模板新建”。
- 项目状态建议：`配置中 / 待运行 / 运行中 / 已出图 / 只读案例`。

### 4.3 视觉工作台 `/projects/:id/canvas`
默认项目页。专注布局、自定义可执行图、覆盖式检查器、运行抽屉——全部规则见 docs/12，执行模型见 docs/15。

### 4.4 批量任务 `/projects/:id/batch`
- 顶部必须先**选择已发布工作流版本**（下拉：vN，默认最近发布；草稿不可选）；
- 生产队列表格：商品组、当前节点、版本、验收分、暂停/继续/仅重试失败；
- 进度与状态计数、并发提示（分析 2 / 生成 1）、最坏调用预算；
- 商品级错误隔离，系统级错误整批暂停（沿用现有引擎语义）。

### 4.5 素材库 `/projects/:id/assets`
左筛选（类型/来源/尺寸/时间）、中央网格、右详情（尺寸、来源节点、**使用位置：被哪些版本/运行引用**）。素材类型：参考图、商品图、生成结果；外部案例图仅来自真实运行/用户上传，不内置假图。

### 4.6 运行记录 `/projects/:id/runs` 与详情
以**一次工作流执行**为单位（不是零散模型调用）：
- 列表：状态、类型（单件/批量）、**工作流版本 vN**、开始时间、耗时、调用数、结果；
- 详情：按执行计划的节点时间线、每步输入来源（数据绑定）、产物 V1/V2、四维验收、修复、错误诊断、原始响应（折叠）、复现参数（版本+输入，只读）。

### 4.7 设置 `/projects/:id/settings` 与 `/settings`
项目内三组：
- **项目**：名称、备注；删除需确认，并级联清草稿 / 版本 / 运行 / 素材 / 批量任务；
- **模型连接**：现有双通道表单。密钥保存在当前浏览器标签页会话，对所有项目共用，不是按项目分开的；
- **生成默认值**：用途 / 比例 / 分辨率 / 数量，只作用于之后新加入的「商品场景生成」节点，不改已有节点。

无项目时的 `/settings` 只有模型连接。顶栏状态灯与「更多 → 设置」进入同一页；状态灯定位到模型连接。画布缺 Key 时仍用模型设置弹窗作为运行闸门，不离开画布。不设主题、隐私空卡片、协作或按项目 Key。

## 5. 草稿 / 版本 / 运行的信息归属（关键）

- 画布默认编辑**草稿**；发布产生不可变**版本**；运行永远引用版本 id。
- 项目列表“工作流状态/版本号”来自最新已发布版本与是否有未发布改动。
- 批量只能选版本；单件试运行可选“无错误的当前草稿”或已发布版本，但落库的运行记录会写明所用内容快照。
- 删除项目级联删除草稿/版本/运行/素材引用（docs/15 §10、数据层迁移附录）。

## 6. 全站状态覆盖
首次使用、空、加载中、运行中、等待人工确认、成功、部分成功、可恢复错误、不可恢复错误、未配置模型、离线/保存失败——每页与关键组件都要覆盖。未配置 Key 只禁止真实模型运行，不隐藏官网、项目、画布结构、节点库、校验与发布能力。

## 7. 文案规则
面向用户命名，不暴露类名/schema/阶段编号；动作动词统一（确认配方、发布版本、运行工作流、暂停任务、重试失败项）；错误说明“问题+影响+下一步”；技术详情默认折叠。

## 8. 边界
不删除或伪造现有业务数据；不绕过状态机、人工确认、代理白名单与 Schema 校验；新增的自定义能力只能编排**既有 runner**，不引入代码执行/任意 HTTP/循环（docs/15 §11）。

## 附录 A · 持久化与数据版本迁移（DB v4）

> 当前实现（v3）：stores = `workflows`（`wf:<pid>`）、`batch`（`batch:<pid>`）、
> `projects`（`list:projects`、迁移标记）、`canvasView`（`view:<pid>`）。

v4 新增（只增不改旧键，保证可回滚）：

| store | 键 | 内容 |
|---|---|---|
| `workflowDrafts` | `draft:<pid>` | 当前草稿（图、校验态、basedOnTemplateId、publishedVersionId） |
| `workflowVersions` | `ver:<pid>:<versionNo>` 与索引 `vers:<pid>` | 不可变版本（图快照 + 固化 plan + checksum） |
| `runs`（新增） | `run:<pid>:<runId>`、索引 `runs:<pid>` | 单次运行（type、versionId、计划步骤结果、attempts、诊断） |
| `assets`（新增） | `assets:<pid>` | 素材清单与使用位置（dataURI 大对象可沿用引用，不强制搬移） |
| `projects` | 追加字段 | `publishedVersionId`、`hasDraftChanges` |
| `canvasView` | 扩展 | 视口/位置按草稿保存；查看版本时用只读覆盖 |

迁移步骤（幂等、可重复执行）：
1. 打开 v4：新 store 经 `onupgradeneeded` 建立，旧键原样保留。
2. 对每个 project：用代码内置标准模板（来自现有 `fixedWorkflow` 图工厂，单一事实源）生成
   草稿 `draft:<pid>` 与已发布 `ver:<pid>:1`，回填 `project.publishedVersionId='v1'`。
3. 旧 `wf:<pid>` / `batch:<pid>` 标记为“历史运行”，在运行记录中只读展示；不强制改写其内部结构。
4. `Batch` 增加 `workflowVersionId`（旧数据缺省视为模板 v1 快照）。
5. 任何迁移项失败不影响项目可打开：失败项目进入“草稿待修复”态并给出原因。

回滚：应用代码若回退到 v3，忽略新增 store/字段即可，旧 `wf/batch/projects/canvasView` 仍可读；
版本不可变保证历史运行始终能按其版本只读复现。
